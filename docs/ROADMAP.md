## 后续阶段一 · 快照 diff 与有效期闭环

1. 前后导入快照 diff：新增上舰 / 疑似到期 / 等级变更 → 生成 `guard_event`。
2. 有效期核算：以购买事件时间 + 购买月数为准；快照消失只标记 `expire_suspected`，绝不自动删除或降级档案。
3. 补齐「手动导入该日名单」入口；不承诺追回缺失快照。

**验收点**：分页不漏人、diff 结果可逐条追溯；数据写入全程可离线完成。

## 后续阶段二 · 加密升级（回到需求文档目标）

1. 评估本机具备 Perl / NASM / OpenSSL 构建链后，将 `rusqlite` 切换到 `bundled-sqlcipher-vendored-openssl`，实现**全库 AES-256 加密**。
2. 数据库密钥由 DPAPI 保护的 `app.key` 派生；提供一次性迁移命令：旧库读出 → 新加密库写入 → 校验记录数 → 保留旧库备份。
3. `crypto.rs` 的字段级加密可保留作为纵深防御，也可在验收后按需收敛；`backup.rs` 的备份整体加密保持。
4. 更新 `ARCHITECTURE.md` 的「可审计偏差」章节，移除降级说明。

**验收点**：迁移前后记录数与抽查字段一致；旧库可回退；无密钥时应用明确报错而非静默打开空库。

## 不变的验收基线（每次回归都要检查）

- 数据不出本机：无云端端点、无遥测、无外部网络请求。
- CSV / Excel 导入通道始终可用，且手动锁定字段不被覆盖。
- 启动自动备份、最近 7 份滚动、一键恢复向导始终可用。
- 三套主题即时切换、关窗最小化到托盘、错误文案人类可读。
- 昵称含空格、`丶`、生僻字与纯数字形态均原样保留；**数字形态昵称不得自动当作 UID**。
- 任何完整地址展示 / 导出都有二次确认；生日年份不出现在提醒文案；敏感字段不明文落盘、不进日志与备份清单。
