# 后续演进路线 · vtuber-fans-admin

> 本文只描述**后续接入步骤与验收点**。`../requirement-doc.md` 是唯一需求依据；本期（核心 MVP）已完成范围见 [`DESIGN.md`](./DESIGN.md) 与根 `README.md`。
> 所有条目均保持「手动导入为不变底座」，任何同步能力失败都必须可手动补录。

## 阶段一 · 大航海 HTTP 快照同步（F2 / L1）

1. 在 `src-tauri/src/sync/` 新增 `http_snapshot.rs`，实现 [`ARCHITECTURE.md`](./ARCHITECTURE.md) 中已定义的 `SyncSource` trait；依赖倒置，不改 `profile.rs` / `import.rs`。
2. 端点 `GET https://api.live.bilibili.com/xlive/app-room/v2/guardTab/topListNew`，参数 `roomid` / `page` / `page_size`，解析 `data.top3` 与 `data.list`（`uid`、`username`、`guard_level` 1 总督 / 2 提督 / 3 舰长、`rank`）。
3. 分页拉取全量名单，写入 `guard_snapshot` + `guard_snapshot_member`；`snapshot_date` 唯一约束防重复。
4. 前后快照 diff：新增上舰 / 疑似到期 / 等级变更 → 生成 `guard_event`（`source='snapshot'`）。
5. **有效期核算**：以购买事件时间 + 购买月数为准；快照消失只标记 `expire_suspected`，绝不自动删除或降级档案。
6. 调度：应用启动时 + 每日可配时刻（默认 04:00）；手动触发 5 分钟冷却；完整浏览器级 headers；不高频轮询。
7. 失败降级：连续失败 2 次 → 托盘通知「今日在舰名单未同步，请检查网络或手动补录」；保留「手动导入该日名单」入口；不承诺追回缺失快照。

**验收点**：分页不漏人；重复同步不产生重复快照；diff 结果可逐条追溯；断网时界面显示「网络不可达 / Cookie 过期」并提供重新同步按钮；手动导入仍可独立完成同样的数据写入。

## 阶段二 · 登录凭证与扫码（F7 联动）

1. Tauri 内置 WebView 打开 B 站登录页，扫码成功后从 WebView Cookie 存储提取 `SESSDATA` 等凭证。
2. 凭证经 `crypto.rs` 加密保存（复用字段级 AES-256-GCM + DPAPI 主密钥），日志零明文。
3. 每次同步前校验登录态；失效 → Toast 通知 + 界面横幅引导重新扫码。
4. 设置页解除 Cookie / 每日快照时刻 / WS 开关的禁用态；首启引导恢复为「扫码登录 → 选择备份目录 → 完成」三步。

**验收点**：凭证不明文落盘、不进日志；过期后可无命令行重新登录；用户文案明确「基于主播自身账号可见数据的低频同步，不保证实时」。

## 阶段三 · 直播期 WebSocket 事件（F2 / L2）

1. `getDanmuInfo` 取 Token 建立直播 WebSocket，解析 `LIVE_OPEN_PLATFORM_GUARD` 等 CMD（`uname`、`guardLevel`、`guardUnit`、`price`）。
2. 检测到开播后自动连接、下播后断开；事件写入 `guard_event`（`source='websocket'`），含 `unit_months` 与 `price_yuan`。
3. 状态栏显示订阅状态；断线显示「实时事件订阅中断」，不影响快照通道。
4. **降级**：协议变更 / 连接失败自动退化为「仅快照」模式，核心档案与在舰列表不受影响。

**验收点**：断线不阻塞快照；同一购买事件不重复计入收入；WS 不可用时手动导入仍完整可用。

## 阶段四 · 纪念日全局提醒（F3）

1. 每日首次启动计算未来 3 天（可配提前天数）的生日 / 上舰周年 / 观看纪念日，写 `reminder_ack`。
2. 汇总卡片 + Windows 原生 Toast；关闭卡片后托盘角标保留未处理数量，直到标记已处理或次日重置。
3. 快捷操作：复制预设祝福话术 / 标记已处理 / 跳转粉丝档案。
4. 注意生日与地址均为加密字段，脱敏逻辑复用 `crypto.rs`，不得在提醒文案中泄露完整值。

**验收点**：最小化到托盘仍收到 Toast；未处理数量准确；提醒不泄露完整生日年份与地址。

## 阶段五 · 舰礼寄送台账（F4）

1. 地址批量补录与 CSV 导入，审核状态 `none / pending / valid / invalid / shipped` 流转。
2. 寄送批次 → 选择在舰成员 → 生成寄送清单 → 逐条发货状态与快递单号。
3. 地址列表默认折叠，单条展开二次确认；导出先给脱敏预览，确认后才允许导出完整地址。
4. 支出记录关联批次，形成批次成本核算（与阶段六联动）。

**验收点**：任何完整地址展示/导出都有二次确认；脱敏预览不含电话与门牌号；批次成本核算可追溯到单条支出。

## 阶段六 · 主播记账本（F5）

1. 收入侧自动归集来自 `guard_event` 的购买/续费（含快照 diff 推断的续费）+ 手动收入。
2. 支出侧：舰礼采购、快递、平台手续费（手动或按比例估算）。
3. 统计视图：月 / 季度支出趋势、大航海收入与舰礼支出净额趋势（前端已有 `recharts` 依赖）。
4. 从「占位页」升级为完整页面，保持现有导航与主题不变。

**验收点**：同一事件不重复计入；支出可关联寄送批次；趋势图在数据量增长后仍流畅。

## 阶段七 · 加密升级（回到需求文档目标）

1. 评估本机具备 Perl / NASM / OpenSSL 构建链后，将 `rusqlite` 切换到 `bundled-sqlcipher-vendored-openssl`，实现**全库 AES-256 加密**。
2. 数据库密钥由 DPAPI 保护的 `app.key` 派生；提供一次性迁移命令：旧库读出 → 新加密库写入 → 校验记录数 → 保留旧库备份。
3. `crypto.rs` 的字段级加密可保留作为纵深防御，也可在验收后按需收敛；`backup.rs` 的备份整体加密保持。
4. 更新 `ARCHITECTURE.md` 的「可审计偏差」章节，移除降级说明。

**验收点**：迁移前后记录数与抽查字段一致；旧库可回退；无密钥时应用明确报错而非静默打开空库。

## 不变的验收基线（每阶段都要回归）

- 数据不出本机：无云端端点、无遥测；网络仅指向 B 站同步接口。
- 手动新建 / CSV / Excel 导入通道始终可用，且手动锁定字段不被同步覆盖。
- 启动自动备份、最近 7 份滚动、一键恢复向导始终可用。
- 三套主题即时切换、关窗最小化到托盘、错误文案人类可读。
- 昵称含空格、`丶`、生僻字与纯数字形态均原样保留；**数字形态昵称不得自动当作 UID**。
